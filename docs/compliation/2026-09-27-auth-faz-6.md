**Durum:** Backend tamamlandı, 27 Eylül 2026. Task'lar: `ALP-AUTH-18` (GitHub login), `ALP-AUTH-19` (GitHub hesap bağlama). **Faz Gate'i testlidir;** gerçek GitHub OAuth App ile uçtan uca doğrulama kullanıcı kontrolü bekliyor (testler sahte credential kullanır ve GitHub'a bağlanmaz).

## Kapsam ve onaylı kararlar

1. `GITHUB_CLIENT_ID` ve `GITHUB_CLIENT_SECRET` `.env.example` ve `.env` dosyalarına boş olarak eklendi. Yeni bağımlılık ve yeni migration yok (V6 `GITHUB` değerini zaten kabul ediyor).
2. `user:email` scope'u kullanılır; `GET https://api.github.com/user/emails` çağrılır ve yalnız **primary ve verified** email kabul edilir. Yoksa giriş `email_not_verified` ile reddedilir.
3. Otomatik hesap birleştirme yok (`account_exists`), Faz 5 ile aynı.

## API ve güvenlik sözleşmesi

Ayrıntılı tablo: `.agents/SECURITY.md` §11 "Auth Faz 6 endpoints".

| Endpoint | Kimlik | Başarı | Önemli hatalar |
| --- | --- | --- | --- |
| `GET /api/v1/auth/oauth2/authorization/github` | Public (yalnız GitHub yapılandırıldıysa) | `302` → `github.com` (state, PKCE) | `403` kapalı/bilinmeyen provider, `429` |
| `GET /api/v1/auth/oauth2/callback/github` | Public, GitHub çağırır | `302` → `FRONTEND_URL/` (cookie'ler) veya `/?oauth_link=<kod>` | `302` → `/login?oauth_error=email_not_verified\|account_exists\|access_denied\|provider_error` |
| `POST /api/v1/auth/oauth/{provider}/link` | Access cookie + CSRF | `200` `{authorizationUrl}` | `401`, `403`, `404` |
| `POST /api/v1/auth/oauth/{provider}/unlink` | Access cookie + CSRF | `200` | `401`, `403`, `404`, `409` |

**Yeni public endpoint'ler:** iki GitHub GET yolu (yalnız yapılandırıldıysa). **Yeni ENV:** iki anahtar. **Yeni dış çağrı:** `api.github.com/user/emails`. **Migration/bağımlılık:** yok. Bunlar güvenlik mimarisini etkiler; incelemenizi rica ederim.

## Açık konular

- Gerçek GitHub akışı henüz denenmedi (Gate). OAuth App gerekir.
- GitHub'ın PKCE'yi desteklediği varsayıldı (`withPkce()`); gerçek denemede doğrulanmalı.
- Eşzamanlı ilk giriş yarışı, reverse proxy/forwarded header, production'da flow session cookie `Secure` ayarı ve bellek içi rate limit konuları Faz 5 kaydındaki gibi açıktır.
- `/user/emails` çağrısı başarısız olursa giriş `email_not_verified` ile reddedilir (güvenli taraf).
- Frontend `/login?oauth_error=` ve `/?oauth_link=` sonuçlarını göstermeli (Faz 9).

## Kullanıcı kontrolü

1. GitHub → Settings → Developer settings → OAuth Apps → New OAuth App: **Authorization callback URL** `http://localhost:8080/api/v1/auth/oauth2/callback/github`.
2. `.env` dosyasında `GITHUB_CLIENT_ID` ve `GITHUB_CLIENT_SECRET` değerlerini doldurup backend'i başlatın (`FRONTEND_URL` dolu olmalı).
3. Tarayıcıda `http://localhost:8080/api/v1/auth/oauth2/authorization/github` açın: `FRONTEND_URL/` adresine dönmeli ve `GET /api/v1/auth/me` `200` vermeli.
4. GitHub hesabınızın primary email'i doğrulanmamışsa veya aynı email ile yerel hesap varsa sırasıyla `email_not_verified` / `account_exists` görmelisiniz.
5. Yerel hesapla girip Swagger'dan `POST /oauth/github/link` çağırın, dönen URL'yi tarayıcıda açın; `GET /oauth/identities` bağlantıyı göstermeli. Şifresiz hesapta `unlink` `409` vermeli.
6. `.\mvnw.cmd test` (91 test) ve `.\pre-push\pre-push.cmd` çalıştırın.
7. Yeni public yolları, ENV anahtarlarını ve `api.github.com` çağrısını güvenlik açısından inceleyin.
