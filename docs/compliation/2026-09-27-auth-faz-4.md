# Auth Faz 4 — Refresh rotation ve aktif oturumlar

**Durum:** Tamamlandı, 27 Eylül 2026. Task'lar: `ALP-AUTH-12` (refresh + rotation), `ALP-AUTH-13` (reuse/replay koruması), `ALP-AUTH-14` (aktif oturum API'leri). Faz 5'e geçilmedi.

## Kapsam ve onaylı kararlar

1. Replay algılama: `user_sessions.previous_refresh_token_hash` (V5). Bir önceki refresh token tekrar sunulursa session revoke edilir.
2. Revoke endpoint'leri POST tabanlıdır; CORS (GET/POST/OPTIONS) ve CSRF ayarları gevşetilmedi.
3. `user_agent` saklanır (en fazla 255 karakter, kontrol karakterleri temizlenir); IP saklanmaz.
4. Refresh ömrü sliding 7 gündür; yeni ENV yok. `pom.xml`, `.env`, `.env.example` değişmedi.

Hamza'nın alanına (`project/**`, `squad/**`, `shared/**`) dokunulmadı. Auth, User modülüne yalnız `UserSessions`/`UserAccounts` facade'larıyla bağlanır.

## API ve güvenlik sözleşmesi

Swagger kontrol yolu: `API_DOCS_ENABLED=true` iken `/swagger-ui/index.html`; önce `GET /api/v1/auth/csrf`. Tüm POST'larda `X-XSRF-TOKEN` zorunludur; yanıtlar `Cache-Control: no-store`, hatalar `ProblemDetail`.

| Yöntem / endpoint | Kimlik ve kapsam | İstek | Başarı | Önemli hatalar |
| --- | --- | --- | --- | --- |
| `POST /api/v1/auth/refresh` | Public yol; geçerli `PDA_REFRESH` cookie + CSRF | Body yok | `200`, yeni `PDA_ACCESS`/`PDA_REFRESH` cookie'leri | `401` geçersiz/süresi dolmuş/logout edilmiş/yeniden kullanılmış token (cookie'ler temizlenir; reuse session'ı revoke eder), `403` CSRF, `429` IP sınırı |
| `GET /api/v1/auth/sessions` | Access cookie; USER/ADMIN, yalnız kendi oturumları | Body yok | `200`, `[{id, createdAt, lastUsedAt, expiresAt, userAgent, current}]` | `401` |
| `POST /api/v1/auth/sessions/{sessionId}/revoke` | Access cookie + CSRF; yalnız kendi oturumu | `sessionId` UUID | `200`; mevcut oturumsa cookie'ler temizlenir | `401`, `403` CSRF, `404` başkasına ait/pasif/yok |
| `POST /api/v1/auth/sessions/revoke-others` | Access cookie + CSRF | Body yok | `200`, `{"revoked": 1}` | `401`, `403` CSRF |

Yeni public endpoint `POST /api/v1/auth/refresh`'tir. ## Açık konular

- İki sekmenin aynı anda refresh yapması replay gibi görünüp session'ı düşürebilir; grace window eklenmedi.
- Sliding refresh'in mutlak bir üst sınırı yoktur (aktif kullanılan session süresiz uzar).
- Oturum listesi sayfalanmaz (aktif oturum sayısı küçük varsayıldı).
- Rate limit uygulama belleğindedir; çoklu instance/reverse proxy topolojisinde yeniden tasarlanmalıdır.
- Oturum yönetimi arayüzü Faz 9'dadır. Sonraki faz (Google OAuth) bağımlılık/ENV onayı gerektirir; yalnız kullanıcı yönlendirmesiyle başlanmalıdır.
