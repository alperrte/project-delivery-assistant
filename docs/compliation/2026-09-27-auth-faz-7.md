# Auth Faz 7 – Role / Permission Authorization

Tarih: 2026-09-27 · Sahip: Alper Temiz · Kapsam: ALP-AUTH-20…23

## Kapsam

- **Kanonik rol modeli (ALP-AUTH-20):** `GlobalRole` (USER, ADMIN) ve `ProjectRole` User modülünün public paketine (`com.pda.user`) taşındı. Hamza'nın mock rolleri gerçek, çalışan rollere dönüştürüldü. Proje rolleri (8): PROJECT_MANAGER, BACKEND_DEVELOPER, FRONTEND_DEVELOPER, FULL_STACK_DEVELOPER, AI_ML_DEVELOPER, UI_UX_DEVELOPER, TESTER, ANALYST. **MODERATOR kullanıcı kararıyla kaldırıldı.**
- **Permission politikası (ALP-AUTH-21):** `RolePolicy` rol → `ProjectPermission` eşlemesini tek yerde tutar (deny-by-default). `PlatformPermission` yalnız ADMIN içindir.
  - PROJECT_MANAGER: tüm yetkiler. Developer türleri ve ANALYST: aynı contributor hakları (PROJECT_VIEW, TASK_WORK, ISSUE_PARTICIPATE). TESTER: contributor + TEST_REPORT_WRITE. Çok rol = birleşim.
  - **ADMIN** platform operatörüdür (USER_MANAGE, SESSION_MANAGE, AUDIT_VIEW; Faz 8'de bağlanacak). Proje üyeliği değildir, projelerde örtük yetkisi yoktur.
- **Proje yetki sözleşmesi (ALP-AUTH-22):** `ProjectAccess` `hasPermission(projectId, userId, permission)` ve `permissionsForUserInProject` ile genişletildi. Auth, Project repository/entity'sine dokunmaz.
- **Testler (ALP-AUTH-23):** rol izin/red matrisi, projeler arası red, contributor/Tester'ın proje güncelleme ve arşivlemede HTTP 403 alması, developer'ın yönetim yetkisi olmaması, Tester rapor yetkisi.
