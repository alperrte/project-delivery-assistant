# Auth Faz 8 – Admin Backend

Tarih: 2026-09-27 · Sahip: Alper Temiz · Kapsam: ALP-AUTH-24…27

## Kapsam

- **Admin bootstrap (ALP-AUTH-24):** `AdminBootstrapRunner`, `ADMIN_EMAIL` / `ADMIN_INITIAL_PASSWORD` ile yalnız sistemde hiç ADMIN yokken hesabı oluşturur (ACTIVE, e-posta VERIFIED, BCrypt, `must_change_password=true`). Restart mevcut hesabı yeniden oluşturmaz, şifreyi sıfırlamaz; aynı e-postaya sahip ADMIN olmayan hesabı terfi ettirmez. Boş/geçersiz e-posta veya 12 karakterden kısa şifre (`.env.example` yer tutucusu `change_me` dahil) uyarıyla atlanır; e-posta/şifre loglanmaz.
- **İlk login'de zorunlu şifre değişimi (ALP-AUTH-25):** `POST /api/v1/auth/password/change`. Bayrak açıkken `JwtCookieAuthenticationFilter` yalnız `me`, `password/change`, `logout`, `refresh`, `csrf` yollarına izin verir; diğerleri `403 {"code":"password_change_required"}`. Değişim bayrağı kaldırır, diğer oturumları iptal eder; eski (başlangıç) şifre artık giriş yaptırmaz. Endpoint IP başına 5/10 dk sınırlıdır.
- **Admin kullanıcı yönetimi (ALP-AUTH-26):** liste/detay, disable/enable, kullanıcı oturumlarını listeleme ve iptal (tekil / hepsi). Kendini veya son aktif yöneticiyi disable etmek `409`; disable tüm oturumları iptal eder ve girişi engeller.
- **Admin proje/sistem özeti (ALP-AUTH-27):** `overview`, `projects` (yalnız ad/slug/durum/aktif üye sayısı), `system/status` (DB erişimi ve Google/GitHub/mail/API docs açık-kapalı booleanları; secret değeri yok). Yeni `PlatformPermission.SYSTEM_VIEW`.
- Yetki iki katmanlıdır: URL kuralı `hasRole("ADMIN")` + servis içinde `RolePolicy` denetimi (`AdminAuthorization`).
- Faz 7'den kalan test eklendi: ADMIN, üyesi olmadığı projede `403` alır.

- Bootstrap şifresi için 12 karakter alt sınırı yeni bir davranıştır; mevcut `.env`'deki `ADMIN_INITIAL_PASSWORD` daha kısaysa admin oluşturulmaz (uyarı loglanır).
- `AUDIT_VIEW` için endpoint yoktur (denetim log modülü kapsamda değil); admin işlemleri yalnız actorId/targetId ile loglanır.
- Rol değiştirme veya kullanıcı silme yoktur; yalnız disable/enable.
- Rol→yetki matrisini Hamza nihai hâline getirecek (`note`).

## Kullanıcı kontrol adımları

1. `backend` içinde `.\mvnw.cmd test` çalıştırın (Docker açık olmalı).
2. `.env` içinde 12+ karakterli `ADMIN_EMAIL`/`ADMIN_INITIAL_PASSWORD` ile uygulamayı boş veritabanında başlatın; logda "Initial administrator created" görün (şifre/e-posta loglanmamalı).
3. Swagger'da (`API_DOCS_ENABLED=true`): csrf → login → `GET /api/v1/admin/users` `403 password_change_required` → `POST /api/v1/auth/password/change` → tekrar login → admin endpoint'leri `200`.
4. Normal kullanıcıyla `GET /api/v1/admin/users` → `403`; oturumsuz → `401`.
5. Hamza'yla `ProjectOverview` ve iki repository ekini teyit edin.
