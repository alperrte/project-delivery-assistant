## Yapılanlar

### HMZ-PROJ-47 — Project authorization matrix
- 8 rolden 3'ü (`FRONTEND_DEVELOPER`, `AI_ML_DEVELOPER`, `UI_UX_DEVELOPER`) daha önce `com.pda.project`/`com.pda.squad` testlerinde hiç geçmiyordu; artık `SQUAD_MANAGE`, `CRITERIA_MANAGE`, `REPOSITORY_MANAGE`, `MEMBER_MANAGE` için tüm 7 contributor rolü döngüyle test ediliyor ([SquadApiIntegrationTest#everyContributorRoleIsDeniedEverySquadMutation](../../backend/src/test/java/com/pda/squad/integration/SquadApiIntegrationTest.java), [ProjectCriterionApiIntegrationTest#everyContributorRoleIsDeniedEveryCriteriaMutation](../../backend/src/test/java/com/pda/project/integration/ProjectCriterionApiIntegrationTest.java), [ProjectRepositoryApiIntegrationTest#everyContributorRoleIsDeniedEveryRepositoryMutation](../../backend/src/test/java/com/pda/project/integration/ProjectRepositoryApiIntegrationTest.java), [ProjectApiIntegrationTest#everyContributorRoleIsDeniedMemberManagementAndMutationIsScopedToItsOwnProject](../../backend/src/test/java/com/pda/project/integration/ProjectApiIntegrationTest.java)).
- Authenticated-ama-üye-değil reddi criteria/repository'de eklendi (önceden yalnız "cookie yok" durumu test ediliyordu).
- Cross-project mutation reddi member-role endpoint'lerinde eklendi.

### HMZ-PROJ-48 — Invitation security
- **Yeni özellik:** [ProjectInvitationRateLimitFilter](../../backend/src/main/java/com/pda/auth/infrastructure/config/ProjectInvitationRateLimitFilter.java) — davet create/resend/accept/reject için IP+path başına 10dk'da 10 istek limiti (`AuthRateLimitFilter` ile aynı desen). `SecurityBaselineConfiguration`'a kaydedildi. Bilinçli olarak `auth` modülü içinde tutuldu (Project modülünde olsaydı `auth → project` şeklinde yeni bir ters modül bağımlılığı oluşurdu; mevcut desen zaten diğer modüllerin path'lerini yalnız string olarak bilir, tip import etmez).
- Süresi dolmuş davetin accept/reject/cancel/resend'de reddi test edildi (önceden yalnız domain-unit seviyesinde test ediliyordu).
- Cross-project davet işlemleri (doğru token+id, yanlış projectId) artık 404 döndüğü test edildi.

### HMZ-PROJ-49 — Repository integration security
- SSRF ve credential-sızıntı zaten kapsamlıydı, ek iş gerekmedi.
- Tek eksik: GitHub 5xx'in HTTP seviyesinde (yalnız unit seviyesinde değil) güvenli 503'e düştüğü ve detay sızdırmadığı test edildi ([ProjectRepositoryApiIntegrationTest#connectSurfacesGitHubServerErrorAsSafeUnavailableWithoutLeakingDetails](../../backend/src/test/java/com/pda/project/integration/ProjectRepositoryApiIntegrationTest.java)).

### HMZ-PROJ-50 — Validation / ProblemDetail consistency
- Yeni [ProblemDetailShapeApiIntegrationTest](../../backend/src/test/java/com/pda/project/integration/ProblemDetailShapeApiIntegrationTest.java): Project/Invitation/Criterion/Squad/Repository controller'larının her biri için 400/403/404/409 yanıtlarının yalnız status code'u değil gerçek `ProblemDetail` gövdesini (`status`, `detail`, `Cache-Control: no-store`) doğruluyor — önceden neredeyse hiçbir test gövdeyi kontrol etmiyordu.
- Proje/squad endpoint'lerinin asla 401 değil her zaman 403 döndüğü doğrulandı (security-layer allowlist'i buna göre tasarlanmış).
- Not: security-layer 403 (`detail` yok) ile controller-layer 403 (`detail="Access denied"`) farklı şekilde — kullanıcı kararıyla bu birleştirilmedi, olduğu gibi bırakıldı.
